# 5분 발표 대본

광주 4반 G123 신민서  
주제: 이미지 기반 제품 결함 판정 및 근거 교차 검증 멀티에이전트

## 1. 소개  35초

> 안녕하세요. 광주 4반 G123 신민서입니다.  
> 제 프로젝트는 이미지 기반 제품 결함 판정 및 근거 교차 검증
> 멀티에이전트입니다. 범용 VLM이 낸 판정을 그대로 사용하지 않고,
> 검사 기준서와 코드 규칙, 사람 승인으로 한 번 더 검증하는 것이 목표였습니다.

## 2. 검사 흐름  60초

> 검사는 다섯 단계로 나누었습니다.  
> Observer가 전체 이미지와 분할 이미지를 보고, Cross-Checker가
> 반전 이미지로 여섯 가지 결함 항목을 다시 확인합니다. Spec-Judge는
> 관찰문과 품목에 맞는 검사 기준서 조항을 RAG로 찾습니다.  
> 최종 PASS, REJECT, ABSTAIN은 LLM이 아니라 코드 결정표가 정합니다.
> 근거가 충분하지 않거나 판단이 충돌하면 자동 합격시키지 않고 ABSTAIN으로
> 보류합니다. 그런 다음 사람이 승인하거나 반려하고, 보고서의 관찰문과
> 조항 인용을 다시 검증합니다. LangGraph, Vision MCP, RAG, LangSmith,
> SQLite checkpointer를 연결했습니다.

## 3. 동작 화면  50초

> 첫 화면에서 품목과 이미지를 입력합니다. 검사를 시작하면 각 에이전트의
> 진행 상태가 SSE로 표시됩니다. 중요한 판정이 나오면 사람 승인 화면에서
> 멈추고, 승인 또는 반려 후에 판정, 결함 유형, 신뢰도, 기준서 조항,
> 조치가 포함된 최종 보고서를 만듭니다.  
> 이 화면들은 외부 호출 없이 기능 흐름을 보여주는 fake 백엔드 시연입니다.
> 성능 수치는 다음 슬라이드의 Ollama 실모델 결과입니다.

## 4. 실모델 검증  80초

> MVTec AD의 동일한 dev 52장으로 단독 VLM B0와 전체 에이전트 A를
> 비교했습니다. 모델은 로컬 Ollama의 qwen2.5vl 3B입니다. 오류, 누락,
> ABSTAIN을 빼지 않고 52건 전체를 분모로 계산했습니다.  
> 막대그래프를 보면 A는 6건을 맞혔고, 5건을 틀렸고, 41건을 보류했습니다.
> 이 41건은 정답이 아닙니다. 근거가 약한 결과를 자동 합격으로 바꾸지 않고,
> 사람 검토가 필요하다고 표시한 것입니다.
> 엄격한 전체 시도 정확도는 B0가 28.85퍼센트, A가 11.54퍼센트였습니다.
> 또한 실제 결함 28건은 하나도 올바르게 확정하지 못했습니다. 따라서 현재
> 모델을 자율 결함 판정기로 사용할 수는 없습니다.
> 원인은 앞단 3B VLM이 미세 결함을 놓친 뒤에는 RAG가 이미지의 픽셀 정보를
> 다시 만들어 복구할 수 없었기 때문입니다.

## 5. 결론  45초

> 관찰부터 기준서 검색, 코드 판정, 사람 승인, 보고서 검증까지 연결했고
> 회귀 테스트 685건을 통과했습니다. 현재 결과로는 자율 검사기보다 사람의
> 판단을 보조하는 검사 지원 시스템으로 정의하는 것이 맞습니다.
> 정확도 개선 가설은 실패했지만, 판정 규칙보다 앞단 시각 모델을 먼저 바꿔야
> 한다는 결론은 얻었습니다. 다음에는 결함 탐지를 PatchCore 같은 전용
> 이상탐지 모델에 맡기고, VLM은 설명을 담당하도록 역할을 나눌 예정입니다.

## 마무리 한 문장

> 에이전트 연결 자체를 성공으로 포장하지 않고, 동일 이미지 비교로 실패 원인과
> 다음 모델의 역할을 분리했습니다.

## 질문 대비

### A가 B0보다 낮으면 프로젝트가 실패한 것 아닌가요?

자율 판정 정확도 가설은 실패했고 현재 성능으로는 배치할 수 없습니다. 다만
근거 추적과 사람 승인이 있는 판정 흐름을 완성했고, 동일 조건 비교로 병목이
RAG 뒤쪽이 아니라 앞단 시각 모델임을 확인했습니다.

### 41건을 보류했으면 사람이 거의 다 판단해야 하는 것 아닌가요?

맞습니다. 현재 coverage는 21.15퍼센트에 불과해 자동화 성능은 부족합니다. 다만 근거가
약한 결과를 억지로 확정하지 않았고, 이 보류율을 다음 모델 교체의 비교 지표로
사용할 수 있게 남겼습니다.

### ABSTAIN을 오답으로 계산한 이유는 무엇인가요?

보류를 분모에서 빼면 실제 자동 처리 성능보다 정확도가 높게 보입니다. 그래서 오류,
누락, ABSTAIN을 포함한 전체 52건을 분모로 고정했습니다.

### RAG를 붙였는데 왜 정확도가 올라가지 않았나요?

RAG는 VLM이 만든 관찰문을 기준서와 연결합니다. VLM이 이미지에서 결함을 놓치면
RAG는 그 시각 정보를 복구할 수 없습니다.

### 정확도를 올리기 위해 판정 규칙을 풀 수는 없었나요?

근거가 없는 결과를 확정 PASS나 REJECT로 바꾸면 숫자는 올라갈 수 있습니다. 하지만
정상 오탐과 결함 미검을 확정 판정으로 바꾼 위험이 커서 기존 안전 규칙을 유지했습니다.

### 다음에 가장 먼저 바꿀 부분은 무엇인가요?

판정 규칙보다 앞단 시각 모델을 먼저 바꾸겠습니다. 전용 이상탐지 모델로 결함을 찾고,
VLM은 설명과 기준서 연결을 담당하는 구조를 먼저 검증하겠습니다.
